# 편집·정규화·접근성 보강

2026-10-24 현재 기록이다. 이전 구현 계획의 단계별 테스트 수와 미구현 설명은 당시 기록으로 보존하며, 현재 범위는 이 문서와 compatibility.md를 따른다. 출시 지원 기준은 이번 작업에서 변경하지 않았다.

## 구현한 변경

- **렌더링**: v1 인스턴스별 RenderCache가 독립적인 문단·제목 조각을 재사용한다. 참조/HTML, 컨테이너·코드 등 문맥 의존 블록, 조각 안의 여러 제목, 8MiB 초과 입력은 전체 렌더링으로 폴백한다. 제목 ID 충돌은 문서 전체에서 다시 해결한다. 캐시와 전체 렌더링의 원문 좌표 포함 HTML이 같은지 공식 GFM 672개와 연속 편집 입력으로 검사한다.
- **DOM**: 내용이 같고 좌표만 이동한 블록은 data-start/end/task만 패치한다. 공통 prefix/suffix를 찾아 앞부분 삽입 이후에도 기존 DOM과 text node를 유지한다. 구조나 내용이 달라진 노드만 교체한다.
- **undo**: 같은 입력 종류·편집 문맥·연속 커서·revision에서 750ms 이내 입력을 묶는다. 방향별 삭제도 묶으며 Enter·붙여넣기·명령·IME·커서 이동·원격 revision은 그룹 경계다. 원본 화면에도 적용한다. Rust coalesce_history와 v1 ABI op12가 명시적으로 history를 합친다. 공유 UI는 자기 연산과 선택 bookmark를 함께 묶고 원격 편집은 보존한다. op32는 네트워크 연산을 만들지 않는다.
- **정규화**: delimiter 매칭으로 강조 표기를 처리하고 한 줄 제목은 ATX, 목록은 기존 마커·들여쓰기 규칙으로 정리한다. URL·코드·HTML·Front Matter의 원문을 보호한다. 자체 읽기 렌더링의 의미 fingerprint가 달라지는 후보는 원문을 반환한다. 공식 672개 모두에서 의미 보존과 정규화 멱등성을 검사한다. 내보내기는 문서·선택·history를 바꾸지 않는다.
- **접근성**: 도구 모음은 Tab 진입점 하나와 방향키/Home/End 이동을 제공한다. 토글 상태, 읽기 전용 의미, 편집 안내, 제목으로 이름 붙인 대화상자, 별도 오류 alert, 열 헤더 scope를 적용했다. 읽기 화면은 document 역할로 전환한다. 강제 색상·동작 감소 CSS도 추가했다.
- **정의 목록**: 용어 뒤 빈 줄, 여러 정의·문단, 4열 들여쓰기의 중첩 목록·인용문·코드와 참조 정의를 지원한다. 원문 좌표와 문서 전체 참조의 첫 정의 우선 규칙을 유지한다. 재귀 한도는 24단계다.
- **코드 색상**: Rust 중첩 주석, Python 여러 줄 삼중 문자열, JS/TS 여러 줄 템플릿·중첩 보간, 표현식 시작 문맥의 정규식 리터럴을 처리한다. 렌더링되는 코드 문자는 원문으로 유지한다.

## 검증

- Rust **92개**: 위치·ABI·편집·협업·Markdown·표 투영 검사. 정규화의 672개 의미 보존/멱등성과 캐시의 672개 정확한 출력 동등성은 별도로 포함한다.
- 브라우저 **70개**: 기존 편집기 40, 공유 리치·원본 22, 실제 로컬 RTCDataChannel 8. 타이핑/삭제/원본 undo, 시간 경계, 원격 편집 보존, DOM text node 유지와 좌표 왕복, 키보드 도구 모음·접근성 의미를 검사한다.
- fmt, Clippy, editor/renderer WASM release, Node ABI·독립 렌더러 동등성, 두 SDK 패키지를 확인한다.
- GFM 구조 비교는 **585/672 일치, 87개 불일치**를 유지한다. 정규화/캐시 검사는 전체 GFM 합격이나 독립적인 표준 인증을 뜻하지 않는다. 잔여 정책 근거는 gfm-policy-review.md를 따른다.

## 성능 측정과 한계

incremental-performance.json은 macOS arm64의 native release 렌더러 측정이다. 47,888바이트·1,000문단에서 9회 중앙값은 전체 렌더링 7.384ms, 캐시 경로 6.089ms였다. 마지막 편집에서 조각 1개를 새로 파싱하고 1,998개를 재사용했다. 조각 수에는 빈 줄도 포함된다. 이 값은 단일 환경의 관측이며 성능 보장이 아니다.

일반적인 GFM 의존성을 모두 추적하는 증분 AST가 아니다. 문서 스캔·전체 HTML 응답 생성·WASM 전달은 남아 있고, 복잡한 문서는 전체 파싱을 사용한다. 측정에는 WASM 전달·브라우저 DOM 레이아웃·페인트가 포함되지 않는다. 별도 blob store·rope·piece table 도입은 이번 변경에 포함하지 않았다.

정규화는 문서화한 지원 규칙에 제한되며 모든 동등한 Markdown 문자열을 하나로 합치는 완전한 canonical serializer는 아니다. 의미 검사는 자체 렌더러를 기준으로 하므로 렌더러와 공유하는 잠재적 오류까지 배제하지 않는다. 코드 색상도 언어 전체 문법 검증기가 아니다.

실제 VoiceOver 음성 출력은 사용자 답변에 따라 이번 검증에서 제외했다. 자동 구조·키보드 검사가 실제 스크린 리더 검증을 대신한다고 주장하지 않는다. 모바일·다른 OS/브라우저·실서비스 협업 검증은 별도 범위다.

## 이전 fixture 정리

제목 앵커 검사는 setext가 ATX로 정규화되어도 ID·링크 의미가 보존되는 결과를 검사하도록 변경했다. 100번 목록의 하위 항목은 유효한 5열 들여쓰기를 사용한다. 종전의 4열 입력을 정규화하면서 목록 계층을 바꾸는 동작은 별도 검사에서 원문 유지로 차단한다. 비교 기준을 완화해 통과 수를 늘린 것이 아니다.

```sh
sh scripts/package.sh
node scripts/check_wasm.mjs
node scripts/check_collab.mjs
cargo run --offline --release --example benchmark_incremental
python3 scripts/serve.py --port 8080
```
