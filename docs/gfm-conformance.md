# GFM 분류·계층적 컨테이너·인라인 처리 보강

2026-10-23 개발 버전의 재현 가능한 검사 결과다. 공식 고정 fixture 672개를 같은 HTML 구조 비교 기준으로 실행했다. **265→585개 일치, 407→87개 불일치**이며 시작 시 실패하던 320개를 해결했다. 시작 시 통과하던 예제의 회귀는 없다. 87개는 렌더러의 확장 또는 정책상 차이로 전체 GFM과의 차이가 있다.

## 구현

- 컨테이너: 목록·인용문을 재귀적으로 처리한다. 순서/비순서 목록의 중첩, 마커 종류·시작 번호, tight/loose 항목, 여러 문단과 코드·인용문을 포함하는 항목, lazy continuation과 빈 항목을 구분한다. ul/ol/li/blockquote의 의미 구조를 출력한다.
- 위치: 컨테이너 접두사와 들여쓰기를 제거한 가상 입력의 바이트 범위를 원문으로 매핑한다. 편집·공유 코어가 보유한 원문을 재작성하지 않으며 data-start/end와 task 위치를 원본 UTF-8 좌표로 출력한다. 기존 flat parse API는 편집·정규화·표 투영의 호환성을 위해 유지하며 컨테이너 렌더링 패스가 의미 계층을 만든다.
- 강조: delimiter run의 양쪽 공백·구두점, underscore의 단어 내부 제한, 3의 배수 규칙, opener/closer 소비 방향을 적용한다. 코드·HTML 토큰 내부는 보호하며 링크 라벨의 구분자를 외부 구분자와 연결하지 않는다.
- 링크: 괄호/대괄호 스택과 이스케이프·코드·HTML 토큰 경계를 처리한다. 빈 목적지, angle 목적지, 공백/유니코드 URI 인코딩, 작은/큰따옴표와 괄호 제목, 이미지 대체 텍스트와 중첩 앵커 금지를 지원한다.
- 참조: 여러 줄 목적지·제목, 공백 정규화·대소문자 비교·첫 정의 우선 규칙을 보강했다. 컨테이너를 먼저 순회해 문서 전체 정의를 수집한 뒤 렌더링하므로 뒤쪽 인용문 안의 정의도 앞쪽 링크에 적용된다.
- 보존 정책: 기존 HTML/URL 허용 목록·Front Matter·각주·하이라이트 등은 유지한다. 따라서 명세의 임의 원본 HTML 및 일부 URI를 그대로 출력하지 않는다.

## 남은 불일치 분류

| 진단 원인 | 개수 |
| --- | ---: |
| 강조 구분자 매칭 | 2 |
| 괄호·링크·참조 정의 | 3 |
| 자동 링크 | 8 |
| 블록 경계·들여쓰기 | 2 |
| 인라인 코드·이스케이프·개행 | 5 |
| 원본 HTML 정책 또는 파싱 | 62 |
| URL 허용 정책 | 5 |

**진단 분류는 합격 판정을 바꾸지 않는다.** 이번 후속 수정은 526→585개 일치(59개 추가 해결), 146→87개 불일치다. 컨테이너·들여쓰기·구조 공백 진단은 모두 해결했고, 남은 블록 경계 2개는 Front Matter 확장이다. 남은 예제를 정책/확장 근거와 함께 [개별 검토 기록](gfm-policy-review.md)에 명시했다. HTML/URL 신호만으로 의도된 차이라고 자동 판정하지 않는다.

`spec/gfm-classification-baseline.json`은 시작 시점의 265개 통과/407개 실패와 각 실패의 진단 분류를 고정한다. `docs/gfm-classification.json`은 해결/남음/회귀 ID와 남은 모든 예제의 원인·정책 신호·첫 구조 차이를 기록한다. `web/gfm-results.json`에는 672개 전체의 원문·기대 HTML·실제 HTML이 있다. `/gfm-audit.html`에서 결과·명세 영역·원인별 필터로 확인한다.

비교 함수 canonical은 이번 보강에서 변경하지 않았다. 단순히 정책 차이로 재분류하거나 비교를 완화해 통과 수를 늘리지 않았다. fixture 원문과 파생 예제의 출처/CC BY-SA 4.0 표기는 spec/NOTICE.md를 따른다.

## 편집·호환성

이전 테스트에서 GFM과 다르게 허용하던 두 입력은 표준 문법의 수용 사례로 수정했다. 100으로 시작하는 중첩 순서 목록은 앞 문단과 빈 줄로 구분했고, 문단 뒤 참조 정의도 빈 줄로 구분했다. 새로 추가한 검사에서는 일반 문단 중간의 2번 목록이 목록을 시작하지 않는 점과 루트 4칸 들여쓰기의 목록 모양 문자열이 코드인 점을 별도로 검증한다.

모든 입력을 표준대로 정규화하는 기능이나 완전한 GFM AST 편집 API를 새로 보장하는 것은 아니다. 매우 깊은 입력은 재귀 제한을 적용해 안전한 원문 표현으로 남긴다. 선택적 원본 문법 노출과 기존 undo·협업 연산은 유지한다.

## 검증

- Rust 92개: 컨테이너·강조·링크·참조·원문 좌표·깊이 제한과 문서 간 참조 격리 등을 포함한다.
- 브라우저 70개: 기존/확장 40개, WebRTC 8개, 리치·원본 통합 22개. 새 검사는 중첩 구조의 한글/이모지 원문 좌표 왕복, 서식과 undo, 링크의 중첩 앵커 방지, 공유 커서·원본 전파를 포함한다.
- fmt·Clippy·editor/renderer WASM release·Node 실제 ABI 및 672개 독립 렌더러 출력 동등성 검사를 통과한다. GFM 구조 일치 수는 이 회귀 테스트 수와 별도로 보고한다.

```sh
sh scripts/build.sh
node scripts/check_collab.mjs
node scripts/check_wasm.mjs
python3 scripts/audit_gfm.py --check
python3 scripts/serve.py --port 8080
```

통과 기준은 검토 후 gfm-baseline.json으로 갱신했으며 다음 빌드부터 585개 기존 일치 예제의 새 회귀를 차단한다. 모바일 viewport 검사는 실기기 입력기·터치 검증과 구분한다.

이전 통합 20개는 375px viewport에서도 통과했으며 임시 화면 크기는 복원했다. 실제 모바일 키보드·터치 검증은 아니다.

## 정책 유지 후속 수정

탭의 4열 계산과 부분 탭 제거, 여러 줄 밑줄 제목, 펜스의 0~3칸 들여쓰기와 닫힘·info 규칙, 코드 내 빈 줄, 목록 내부의 blank 범위와 빈 항목 종료, 인용문 코드의 lazy continuation 금지를 보강했다. 잘못된 인라인 링크는 shortcut reference로 재해석하고 NBSP는 URL 문자로 인코딩한다. 자동 링크 끝의 불균형 괄호·엔티티와 메일 도메인을 검증하며 www의 HTTPS 기본값은 유지한다. HTML 태그의 구문과 속성 경계를 검증하고 허용 HTML 블록은 빈 줄까지 Markdown을 문자 그대로 처리한다. a의 name 외 속성·미허용 태그·scheme 차단은 유지한다.

가상 탭 공백과 실제 원문 문자가 하나의 선형 data-text 범위를 공유하지 않게 분리했다. 브라우저에서 한글·이모지 커서 왕복과 교체·undo, 공유 원본 전파를 검사한다. HTML 블록 정규화 테스트의 입력 보정 근거는 정책 검토 문서에 기록했다.

후속 편집 보강의 캐시/정규화/undo/접근성 검증은 [편집 보강 기록](editor-hardening.md)을 따른다. 정규화의 의미 보존과 멱등성 및 캐시의 원문 좌표 포함 출력 동등성도 같은 672개 입력으로 검사한다.
