# 협업 코어 v2 설계

2026-10-23. 기존 단일 사용자 구현은 프로토타입으로 보존한다. 기존 API를 협업 API로 가장하지 않고 `src/collab`에 새 코어, `web/collab`에 별도 어댑터를 둔다. 기존 파서·렌더러·붙여넣기 정책·CSS는 재사용 후보이며 원문 좌표와 공유 문서 사이의 어댑터를 교체한다.

## 공유 모델 결정

원문 보존·원본 모드를 유지하기 위해 본문은 문자 단위 RGA 계열 연산 기반 CRDT로 표현한다. 서식 기호도 원문의 일부다. 표는 문서 시퀀스의 구조 객체이며 표·행·열에 안정적인 공유 ID를 부여하고 셀별 Markdown 인라인 원문은 별도의 문자 CRDT로 관리한다. 표 전체 문자열 교체를 공유 편집 명령으로 사용하지 않는다.

이 선택은 원문의 수렴을 보장하는 모델이다. 두 사람이 동시에 Markdown 구분자를 편집하면 병합 후 일시적으로 미완성 구문이 될 수 있다. 서식 의도를 의미적 mark CRDT로 병합하는 방식과는 다르다. 미완성 구문은 기존 정책에 따라 원문으로 표시·보존한다. 향후 요구가 서식 의도 병합까지 포함하면 mark 계층을 별도로 설계한다.

## 식별자와 인과성

- `DocumentId`: 128비트 문서 ID. Markdown 파일명이나 표시 제목과 독립적이다.
- `ActorId`: 독립적으로 기록하는 복제본의 무작위 128비트 ID. 같은 사람이 여러 탭·기기를 사용하면 서로 다른 ID를 쓴다.
- `OpId`: Lamport counter(u64) + ActorId. 문서 전체 연산의 유일 ID와 결정적 정렬 기준이다.
- `AtomId`: 삽입 OpId + Unicode scalar index. 바이트 위치가 이동하거나 문자가 삭제되어도 변하지 않는다.
- 연산은 자신이 관측한 causal frontier를 명시한다. 의존 연산이 없으면 bounded pending queue에 보관한다.

시퀀스는 왼쪽 기준 atom/row/column ID 뒤에 삽입한다. 같은 기준점의 형제는 OpId 내림차순으로 정렬하고 하위 항목을 깊이 우선으로 순회한다. 기존 연속 문자 사이에 후속 삽입이 가능하며 동시 문자열의 순서가 결정적으로 정해진다. 삭제된 기준점도 tombstone으로 유지하여 도착 순서가 달라도 참조가 유효하다.

정상 연산은 중복·역순·지연 수신해도 같은 상태로 수렴해야 한다. 잘못된 문서·형식·ID 충돌은 수신 배치를 거절한다. 의미적으로 무효인 연산은 격리·보고하여 나중에 유효한 의존 연산을 수신하는 일을 막지 않는다. 이 모델은 비악의적 복제본을 전제로 한다. ActorId 일치 검사는 사용자 인증이나 서명을 대신하지 않는다.

## 공유 명령과 undo

공유 연산은 text insert/delete, table create, row/column insert/delete, column alignment, operation activation이다. 표 셀은 table/row/column ID로 주소를 지정한다. 삭제된 행·열의 셀 편집은 데이터를 유지하되 화면에서 숨기며 삭제 취소 시 다시 표시한다. 동시 정렬 변경은 활성 연산 중 가장 큰 OpId가 결정한다.

각 로컬 편집은 연산 ID 그룹으로 history에 기록한다. undo/redo는 자기 그룹의 활성 상태를 바꾸는 새 연산을 생성한다. 원격 연산은 로컬 history에 넣지 않고 원격 변경이 로컬 redo를 지우지 않는다. 삽입을 취소해도 그 문자를 기준으로 다른 사용자가 삽입한 문자까지 제거하지 않는다. 두 사용자가 같은 문자를 삭제한 경우 한 사람의 삭제 취소만으로 문자를 되살리지 않는다.

구조 객체 생성 취소·행 삭제는 하위 변경을 숨길 수 있지만 그 변경을 삭제하지 않는다. 객체를 복원하면 다시 조회할 수 있다. 삭제와 수정의 경합을 무조건 수정 우선으로 처리하지 않는다.

## 커서·IME·표현

커서는 원문 바이트 오프셋 대신 좌우 atom ID와 bias를 가진 상대 앵커로 저장한다. UTF-8 좌표는 UI와 코어 경계에서만 사용한다. 원격 변경 뒤에도 앵커를 해석해 선택을 복원한다. grapheme 이동은 브라우저 기본 Unicode 기능을 사용한다.

IME 조합 중 원격 상태 수신과 조합 DOM 렌더링을 분리해야 한다. 조합 시작 시 선택한 atom ID와 삽입 기준점을 캡처하고 commit 시 그 ID만 수정한다. 현재 오프셋 범위를 다시 삭제하여 조합 중 도착한 다른 사람의 문자를 지우면 안 된다.

표 원본 Markdown 편집은 별도 설계 단계다. 출력 Markdown 좌표와 문서 CRDT의 객체/셀 좌표는 다르다. 원본의 표 구간을 구조 명령으로 변환하는 projection/diff 계층과 미완성 원문 정책을 구현하기 전까지 기존 리치 UI를 새 코어에 단순 연결하지 않는다.

## 동기화·전송·저장

코어는 네트워크를 알지 못한다. `export_all`, causal frontier 기준 `changes_since`, `merge`와 bounded binary codec을 제공한다. WebRTC 어댑터는 해당 바이트만 전달한다. DataChannel 연결·시그널링·ICE(STUN/TURN)·방 권한·연결 상태는 호스트/전송 계층의 책임이다.

재연결은 보유 frontier 또는 전체 연산 로그를 교환하여 누락을 복구한다. Markdown 내보내기는 배포/교환 형식이고 협업 재접속 저장 형식이 아니다. DocumentId와 연산 로그를 보관해야 공유 ID·tombstone·인과관계를 유지한다. 같은 ActorId를 재사용하려면 단일 작성자 소유권과 기존 로그 복원을 보장해야 한다.

작업 프레임은 `SCV2`, protocol version 2, DocumentId, 연산 목록의 little-endian binary 형식이다. UTF-8 text 1MiB/연산, 프레임 16MiB, pending 4096개, 전체 로그 100000개를 초기 자원 한도로 둔다. 로그가 커지면 모든 참가자의 안정된 checkpoint를 합의한 뒤 GC·압축하는 별도 프로토콜이 필요하다. 임의로 tombstone을 제거하지 않는다.

첨부 본문을 각 문자 CRDT에 계속 복제하지 않도록 blob/reference 모델은 후속 통합 단계에서 분리한다. 현재 프로토타입의 Base64 첨부 삽입을 그대로 협업 저장 구조로 확정하지 않는다.

## 구현 순서와 완료 기준

1. 공유 코어와 codec: 문자·표 ID, 인과 대기, 수렴, 자기 undo, 앵커, 잘못된 입력 검증.
2. IME 편집 의도 캡처, 전용 WASM ABI, 전송 독립 JS API.
3. WebRTC 전송과 재접속, 로컬 두 복제본 검증 화면. 실제 TURN 운영 환경은 호스트가 제공한다.
4. 기존 리치/원본 UI의 projection 계층 교체, 문법·표·첨부·커서 presence 통합.
5. 실제 다중 기기·네트워크 단절·OS IME·권한·지속 저장·checkpoint 검증.

단계 1~3의 검증 화면은 전체 편집기 v2 출시를 뜻하지 않는다. 현재 구현 상태는 구현 계획과 테스트 결과에 별도로 기록한다.

## 투영 통합 구현

`src/collab/projection.rs`가 Markdown 좌표↔문서/셀 scope를 매핑하고 문자·표 복합 조작을 원자적으로 적용한다. `web/collab/editor_core.js`를 통해 기존 리치·원본 UI에 연결했다. 단순한 전체 원본 덮어쓰기를 기본 공유 편집 명령으로 쓰지 않는다. 미완성 표와 원격 충돌 초안은 별도로 보존한다. 구체적인 지원 경계는 collaboration_api.md를 따른다.

### 데모 ICE 서버 설정

협업 데모의 `STUN / TURN 설정`에서 RTCIceServer 배열(JSON)을 지정할 수 있다. 기본값은 `[{"urls":"stun:stun.l.google.com:19302"}]`이며 Google 공개 STUN에 연결한다. 네트워크가 직접 연결을 차단하면 운영자가 제공하는 TURN 서버의 urls·username·credential을 입력한다. 인증 정보는 브라우저 메모리의 설정란에만 두며 데모는 저장하지 않는다. SDK `connect_local_pair`의 기본 `ice_servers`는 기존처럼 빈 배열이다. ICE 실패/시간 초과 메시지에는 양쪽 ICE 상태가 포함된다.

### 서버 없는 같은 페이지 데모

배포 예제와 로컬 리치 데모는 기본적으로 `같은 페이지 · 서버 불필요` 연결을 사용한다. 데모 전용 MessageChannel 어댑터가 기존 협업 핸드셰이크·분할 프레임·권한 확인·CRDT 병합을 통과시킨다. 직접 원문을 복사하거나 협업 WASM을 우회하지 않는다. 인터넷·STUN·TURN 없이 해당 페이지의 두 복제본만 연결하며 WebRTC 성공으로 표시하지 않는다. 연결 끊기·독립 편집·재연결 병합을 지원한다.

`WebRTC · STUN/TURN`을 선택하면 기존 실제 RTCDataChannel 검증을 수행한다. 이 모드에는 기존 ICE 네트워크 제약이 남으며, TURN 서버 없이 모든 환경의 연결을 보장하지 않는다. 다른 기기로 연결하려면 호스트의 시그널링 및 인증도 필요하다. 데모 전용 어댑터는 안정 SDK API에 포함하지 않는다.
