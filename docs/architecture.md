# 아키텍처

## 현재 구현

Rust의 `Editor`가 원문 문서, 안정적인 줄 노드 ID, UTF-8 선택, revision과 undo/redo를 소유한다. `markdown::parse`가 원문 span을 가진 의미 블록 트리를 만들고, 렌더러가 허용된 HTML과 텍스트별 원문 좌표를 출력한다. WASM ABI는 이 코어를 브라우저에 연결한다.

이번 구현은 원문을 기준으로 편집하고 의미 트리를 파생하는 구조다. 처음 설계한 모든 의미 노드를 직접 수정하는 트리 에디터와 차이가 있다. 이 구조로 미지원 구문·HTML 속성·YAML을 그대로 보존한다. 브라우저의 서식·목록·표 명령은 원문 교체로 변환되어 Rust 트랜잭션으로 적용된다. Rust가 UTF-8 경계·revision·원자성을 검증하고 렌더링 허용 목록을 적용한다.

## 저장과 history

원문은 줄별 `Rc<str>`에 보관한다. 스냅샷은 바뀌지 않은 줄의 본문을 공유하므로 다른 문단 편집이 첨부 본문을 매번 복제하지 않는다. 현재 history 한도는 200개다. 같은 첨부 줄 자체를 수정하면 새 줄 문자열을 생성한다. 별도 blob store·rope·piece table은 아직 적용하지 않았다.

지원 구문만 내보내기에서 정규화한다. 원문 HTML 속성은 렌더링에서 제외되더라도 원문 줄에 남는다. 정규화한 내보내기는 내부 문서를 교체하지 않아 선택과 history를 바꾸지 않는다. 원문 위치를 변환하는 정규화 명령은 아직 제공하지 않는다.

## 입력과 위치

브라우저는 DOM Selection의 UTF-16 위치를 렌더러의 `data-start/end`에 대응시켜 UTF-8 원문 위치로 보낸다. 코어는 이를 `NodeId + byte_offset` 선택으로 저장한다. 인라인 구분자·링크 목적지처럼 표시되지 않는 위치도 원문 좌표로 유지한다. DOM에 투영한 위치가 같더라도 프로그램이 복원한 논리적 위치를 다시 덮어쓰지 않는다.

별도의 `delimiter/attribute` 영역 enum은 아직 없다. 해당 영역의 구체적인 원문 오프셋으로 구분한다. 정방향·역방향 선택, 경계 affinity, 트랜잭션 및 history의 위치 맵을 지원한다. 삭제된 범위 내부 위치의 원래 의미까지 역매핑으로 복원한다고 보장하지 않는다.

사용자가 지우는 문자는 브라우저 기본 `Intl.Segmenter`로 grapheme 경계를 계산하고 Rust가 바이트 범위를 검증한다. Unicode 경계 데이터를 외부 패키지로 포함하지 않는다. 브라우저의 방향키·터치 이동은 네이티브 선택을 사용한다. 이는 Rust 단독 환경의 grapheme 탐색 API를 구현한 것은 아니다.

`compositionstart`부터 `compositionend`까지 조합 DOM의 재렌더링을 미룬다. commit을 하나의 트랜잭션으로 적용하고 중복 최종 입력을 억제한다. 조합 중 외부 문서 교체는 거절하고 설정 변경은 연기한다. 실제 OS 입력기 검증은 합성 이벤트 검증과 별도다.

## 화면 패치

커서 이동은 ABI의 작은 선택 응답만 받고 Markdown을 다시 렌더링하지 않는다. 문서가 바뀌면 현재 Rust 렌더러는 전체 의미 블록을 다시 파싱·렌더링한다. 브라우저는 블록을 비교해 달라진 DOM만 교체한다. 조합 중에는 이 과정 자체를 하지 않는다.

원문 앞부분이 바뀌어 뒤쪽 span 좌표가 이동하면 뒤쪽 블록도 변경으로 판단한다. 향후 의미 블록의 안정 ID, 증분 파싱과 좌표 패치 분리가 필요한 최적화 영역이다. 현재 구현을 완전한 증분 렌더러로 부르지 않는다.

## 임베딩 경계

각 인스턴스의 문서·history·선택은 격리한다. Shadow DOM으로 CSS를 격리하며 기본 본문 스타일과 호스트 등록 레이아웃을 사용한다. Front Matter는 등록된 이름을 선택할 뿐 임의 CSS URL을 지정하지 않는다.

메뉴 복귀 선택·범위·스크롤은 인스턴스 메모리에 보관한다. 열린 동안 직접 범위 편집이 발생하면 해당 위치를 매핑한다. 다른 문서를 불러오면 메뉴를 취소하고 이전 선택을 사용하지 않는다. 첨부 비동기 작업은 revision으로 오래된 결과를 거절한다.

WASM은 생성기가 없는 ABI v1과 선형 메모리를 사용한다. 버퍼 소유권·명령·오류는 [API 문서](api.md)에 기록한다. `core.js`는 호출 후 출력 메모리를 즉시 복사하며 memory growth 전의 view를 재사용하지 않는다.

## 협업 v2 전환 (2026-10-23)

이 문서의 기존 `editor.rs`와 `web/editor.js` 구조는 단일 사용자 프로토타입이다. 협업 문서 상태는 `src/collab`의 독립 CRDT 코어가 소유하고 `web/collab/core.js` 및 `webrtc.js`가 별도 ABI와 전송을 담당한다. 모델·undo·ID·표 좌표는 기존 구현과 다르므로 같은 revision 모델을 공유하지 않는다. [협업 설계](collaboration.md)와 [API](collaboration_api.md)에 새 구조와 UI 통합 경계를 기록했다.
