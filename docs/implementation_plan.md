## 이전 시점 미확정 사항

이 항목은 전체 방향을 재논의할 이유가 아니며 해당 기능을 구현할 때 확정한다. 사용자 결정과 구체화 제안을 구분해 기록한다.

- 표 밖 이동 키 조합, Enter·Backspace·Delete의 표 문맥 동작, 헤더·마지막 행/열 삭제, 방향키 경계와 셀·행·열 드래그 선택의 시작 조작.
- 각주 반복 참조·번호·다문단 정의·돌아가기·미정의/중복/순환 처리, 제목 앵커 충돌 정책.
- 제목 Enter 후 일반 문단, 목록 Enter/병합, 표 전체 삭제, 링크 편집 UI, 코드 줄 번호·제목 단계·문단 보조 표시: 기존 채팅에서 추가 추천한 사항이며 세부 동작은 아직 명시적으로 확정하지 않음.
- HTML `kbd` 허용 여부, URL/상대 경로/srcset/이미지 크기 검증, YAML `layout`에서 해석할 문자열 표현 범위, 닫히지 않은 Front Matter.
- 이모지 지원 별칭 전체 목록, 지원 구문의 나머지 canonical 표기.
- 첨부 파일명 저장 문법, 개별·전체 용량 기본값, 저장소 확장 API.
- 예약 키 충돌 시 대체 바인딩과 편집 영역 탈출 키, 접근성 목표 수준과 지원 브라우저 버전.
- 설정 전체 스키마·오류 정책, WASM wire format·공개 API, 성능 기준 기기·목표 수치.

## 성능 측정

문서 크기·노드 수·최대 표 크기·첨부 크기별로 열기, 입력, 선택, 모드 전환, 붙여넣기, 내보내기, 메모리를 측정한다. 기준 기기·브라우저·WASM 빌드 옵션과 측정 입력을 함께 기록한다. 측정 전 수치를 보장하지 않는다.

## 초기 문단 코어 구현 기록 (이전 단계, 2026-10-23)

`src/editor.rs`는 최소 한 문단을 유지하는 모델과 안정적인 노드 ID, UTF-8 경계 검증, anchor/focus 선택, 여러 단계의 원자적 텍스트 교체를 제공한다. 줄바꿈 삽입은 문단 분할, 문단 경계를 포함한 범위 삭제는 병합이다. 원문 Markdown 해석이나 키보드 Backspace/Delete 명령 자체를 구현한 것은 아니다.

revision 불일치와 잘못된 최종 선택은 적용 전에 전체 작업을 거절한다. 실제 문서 변경에만 history를 추가하고 undo/redo도 revision을 증가시킨다. 선택만 변경하거나 아무것도 바뀌지 않으면 history를 생성하지 않는다. 메뉴 등에서 저장한 위치는 트랜잭션의 `PositionMap`으로 새 문서에 매핑할 수 있다. history도 역순 step 매핑을 반환한다. 삭제된 범위 내부 위치는 affinity에 따라 경계로 이동하며, 삭제 전 내부 위치를 매핑만으로 복구한다고 보장하지 않는다.

history는 현재 문서 스냅샷 방식이며 입력 묶음·용량 제한·공유 저장 최적화는 아직 없다. 첨부 기능을 붙이기 전에 공유 저장 구조로 변경해야 한다. 아직 문법 구분자/속성 영역의 논리적 위치는 없고 문단 텍스트 위치만 지원한다. `plain_text()`는 문단을 LF로 연결하는 개발용 교환 형식으로 Markdown 직렬화와 다르다.

표준 테스트 총 14개(위치 변환 4개, 코어 통합 10개), Clippy, 포맷 검사, WASM 릴리스 빌드가 통과했다. 코어 통합 테스트에는 한글·이모지·결합 문자·여러 문단의 모든 유효 범위 교체와 undo 왕복도 포함된다. 이는 grapheme 단위 커서 이동 검증이 아니다.

## 브라우저 구현 후 선택한 기본 동작 (2026-10-23)

- Esc로 편집 영역을 빠져나가고, 표 메뉴의 앞/뒤 이동 또는 경계 방향키로 표 밖에 이동한다. 필요하면 빈 문단을 만든다. 첫 셀 Shift+Tab도 표 앞으로 이동한다.
- 표 셀 Enter는 `<br>`, 본문 Enter는 새 문단, 목록 Enter는 다음 항목, 빈 항목 Enter는 목록 종료다. 헤더 앞 행 삽입은 첫 본문 행 위치에 삽입한다. 헤더 삭제 시 다음 행을 헤더로 사용하며 전체 행·열 삭제는 표 삭제다.
- 제목 대체 키는 mod+alt+1~6, 모든 도구는 mod+shift+p 팔레트에서 접근한다.
- 파일명 저장 규약은 Markdown 링크 제목 `attachment-uri:<URI 인코딩 파일명>`이다. 이전 `attachment:` 형식도 읽는다. 이미지·파일 기본 한도는 4MiB/16MiB, ABI 입력·문서는 32MiB다. 설정에서 첨부 한도를 변경할 수 있다.
- 지원 이모지 별칭 10개는 `markdown::EMOJI`에 직접 관리한다. 전체 목록은 호환성 문서에 기록한다.
- URL은 http/https, 일반 링크의 mailto, 상대·섹션 경로를 지원한다. 인라인 이미지 data URL은 래스터 MIME만, 일반 파일 data URL은 명시적 첨부 다운로드에만 허용한다. 임의 style·이벤트 속성은 렌더링하지 않는다.

이는 이번 구현의 기본값이며 기존 사용자 결정과 구분한다. 처음 목표 범위 전체를 완료했다고 간주하지 않는다. 남은 적합성·실환경 검증과 구현 한계는 [호환성](compatibility.md)에 기록한다.

## 현재 검증

Rust 위치/코어/파서·ABI 표준 테스트, Clippy, 포맷, WASM 릴리스 빌드, Node에서 실제 WASM ABI 호출, 브라우저 수용 테스트를 수행한다. 입력이 잘못됐을 때의 원자성, 미지원 원문 보존, 코드·YAML·주석 보호, 자동 변환 undo/redo, 첨부 재열기, 표 조작을 포함한다. 적대적·미완성 조각 17종의 3중 조합도 파서에 통과시켜 panic을 검사한다.

성능 결과는 `performance.json`에 기록한다. 브라우저 DOM 비용과 OS IME 실검증은 해당 수치·합성 이벤트 테스트에 포함되지 않는다. 테스트 실행 방법은 README를 따른다.

2026-10-23 검증 기록: Rust 테스트 34개, 로컬 브라우저 수용 테스트 29개 통과. Clippy·포맷·WASM 릴리스 빌드·Node ABI 검증과 배포 tar 패키징을 확인했다.

## 확장 문법 구현 기록 (2026-10-23)

사용자가 지정한 확장 문법 페이지를 대조해 `==하이라이트==`, `{#id}` 제목 접미사, 정의 목록, 코드 기본 어휘 색상, `:tent:`/`:joy:`를 추가했다. 위/아래 첨자 Markdown 문법은 후속 요청에 따라 제외했다. HTML mark는 속성 없이 표시하며 HTML 붙여넣기에서도 하이라이트와 정의 목록 의미를 유지한다. 하이라이트 툴바·명령·자동 닫기·모드 노출·자동 변환 undo를 적용했다.

Rust 54개(문법 테스트 6개 추가), 기존/확장 브라우저 33개(4개 추가), Clippy·fmt·WASM release와 Node 실제 협업 ABI 검증을 통과했다. 협업 브라우저 수용 테스트 8개도 통과했고 표 셀의 하이라이트 렌더링 검사를 포함한다. 코드 어휘 색상은 기본 토큰 분류이며 전체 프로그래밍 언어 문법이나 모든 Markdown 방언 적합성 인증이 아니다. 예제는 `/extended.html`과 `/extended.md`다.

## 공유 리치·원본 및 GFM/실입력 검증 (2026-10-23)

기존 UI를 replica 옵션으로 v2에 연결했다. 표/셀 좌표 투영, 안정적 구조 명령, 복합 undo 그룹, 상대 선택·redo caret, 원본 초안과 원격 충돌 보존을 구현했다. 불규칙 GFM 표의 무시된 초과 셀은 원문으로 보존한다. 전체 문서 교체는 명시적 교체이며 표 ID 재생성이 가능하다.

공식 GFM 672개 전체 예제의 구조 비교를 추가했고 동일 비교 기준으로 191→262개 일치로 개선했다. 나머지 410개는 기록하며 전체 적합성 완료를 선언하지 않는다. macOS Firefox 두벌식은 실제 키 이벤트로 리치·원본 조합 중 원격 삽입까지 확인했다. 모바일 viewport 검사는 실기기 검증과 구분한다. 자세한 결과와 재현 방법은 [검증 기록](validation.md)을 따른다.

최종 자동 검사: Rust 65개, 브라우저 56개(기존/확장 34 + 전송 8 + 리치/원본 14) 통과. 리치/원본 14개는 375px에서도 재검사했다. 실제 두벌식은 최종 코드에서 리치·원본 조합 중 원격 삽입을 재확인했다. GFM 262/672 결과는 별도 적합성 현황이며 전체 합격 집계에 포함하지 않는다.

## UI 통합 추가 수용과 핸들 순서 이동

여러 표를 가로지르는 원본 교체와 escape·모드 전환·undo/redo를 추가 수용 검사로 확인했다. 표 핸들 드래그 이동, Shift 범위 선택, Alt+방향키 및 표 도구 이동 명령을 구현했다. 공유 모델에 ID 기반 Reorder 연산·codec/ABI를 추가하고 단일 사용자 UI에도 같은 조작을 연결했다. 머리행은 고정한다. 검사 현황·충돌 규칙은 validation.md와 collaboration_api.md를 따른다. 호스트 영구 저장·blob·presence·다중 기기 TURN 및 전체 GFM 등은 별도 미완료 범위다.

## GFM 계층·delimiter/link 보강

공유 파서/렌더러에 재귀 컨테이너 패스, 원문 좌표 매핑, delimiter run 매칭, 대괄호/목적지 파서와 전역 참조 수집을 추가했다. 기존 API·협업 문서 모델을 유지하며 표준 문법과 다른 이전 수용 예제는 별도 기록했다. 같은 기준의 585/672 일치·87 불일치와 남은 원인별 목록은 gfm-conformance.md 및 gfm-classification.json에 공개한다. 실제 미구현 규칙과 정책 신호를 구분하며 전체 GFM 완료로 처리하지 않는다.
