# 문법과 저장 규칙

이 문서는 목표 명세다. 구현 완료 여부는 [구현 계획](implementation_plan.md)에서 관리한다. 정규화는 지원 구문에만 적용하고 미지원 원문을 추측해서 다시 쓰지 않는다.

## 문서 요소

| 영역 | 요소 및 규칙 |
| --- | --- |
| 블록 | 문단, H1~H6, 수평선, 인용문, 순서·비순서·작업 목록, 표, 코드 블록 |
| 인라인 | 텍스트, 굵게, 기울임, 취소선, 하이라이트(`==내용==`), 코드, 링크, 이미지, 이스케이프, soft/hard break |
| 확장 | 각주 참조·정의, 알림, 이모지 별칭, 정의 목록, `{#id}` 제목 ID, 사용자 앵커, 접기, picture |
| 원문 | HTML 주석, Front Matter, 미지원·미완성 구문 |

굵게는 `**텍스트**`로 저장한다. 중첩 서식은 의미를 유지한다. 기울임·목록 표식·코드 fence의 정확한 canonical 표기는 호환성 fixture를 작성하며 확정한다. 코드의 구분자 충돌을 피할 수 있어야 한다.

목록의 하위 단계 들여쓰기는 상위 항목 기준 `max(4, 상위 표식과 뒤 공백의 폭)`칸을 추가한다. 예: `100. ` 아래는 5칸 이상 필요하다. 들여쓰기도 정규화 대상이다.

강제 줄바꿈은 줄 끝 공백 두 칸 이상+개행, 백슬래시+개행, `<br>`, `<br/>`, `<br />`를 읽고 `HardBreak`로 통일하여 `<br>`로 저장한다. 표 셀도 같은 표현을 사용한다. 일반 개행은 soft break, 빈 줄은 문단 경계로 구분한다. 코드 안에서는 `<br>`를 문자 그대로 유지한다.

표는 헤더·열 정렬·행·셀 구조를 보존한다. 병합 셀은 문서 모델에 허용하지 않는다. 셀 내용의 파이프 이스케이프와 코드 내 파이프는 파서·직렬화 공통 fixture로 검증한다.

알림 유형은 `NOTE`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`이다. 각주의 세부 참조·번호 정책은 아직 제안 단계이므로 구현 전 별도 명세로 확정한다.

일반·상대·섹션 링크, 제목 앵커, 사용자 지정 앵커를 지원한다. URL 괄호 처리와 중복 제목 앵커 생성 정책은 fixture로 명시한다.

## HTML

원문 HTML과 렌더러가 생성하는 DOM 태그는 서로 다른 목록이다. 다음은 **원문에서 허용할 HTML**이다.

| 요소 | 렌더링 허용 속성 |
| --- | --- |
| `br`, `mark`, `sub`, `sup`, `ins`, `picture`, `summary` | 없음 |
| `a` | `name` |
| `img` | `src`, `alt`, `title`, `width`, `height` |
| `source` | `srcset`, `media`, `type` |
| `details` | `open` |
| `<!-- ... -->` | 한 줄·여러 줄 주석 원문 |

일반 Markdown 링크가 생성하는 `href`는 위 원문 `a` 속성 목록과 별도다. 미허용 속성은 표시에서 제외하지만 문서 원문 정보에 남기고 리치 편집 후 저장에도 보존한다. `style`과 이벤트 속성은 렌더링하지 않는다. 미지원 태그는 실행하지 않고 RAW로 표시·보존한다. 원문 주석은 편집 화면에서 구분자를 포함한 회색 원문으로 직접 편집하며 읽기·미리보기에서는 숨긴다.

현재 기본 정책은 http/https·상대·섹션 경로, 일반 링크의 mailto다. 제어 문자·역슬래시·프로토콜 상대 URL은 거절한다. srcset은 후보별 URL을 검증하고 이미지 크기는 1~10000의 정수만 표시한다. Base64 이미지는 PNG/JPEG/GIF/WebP/AVIF MIME만 인라인으로 허용하고 명시적 첨부 data URL은 다운로드로 처리한다. 이 정책은 이번 구현 기본값이며 기존 합의에서 미확정이었던 항목을 구체화한 것이다.

## Front Matter와 이모지

문서 맨 앞 `---`로 시작하는 YAML Front Matter는 본문과 분리하고 원문을 보존·편집한다. 전체 YAML 파서는 구현하지 않는다. 레이아웃 적용에 필요한 최상위 `layout` 문자열만 제한적으로 읽는다. 복잡한 YAML 표현·해석 불가 값은 원문을 유지하고 레이아웃 폴백을 적용한다. 닫히지 않은 Front Matter의 경계 처리도 fixture로 확정한다.

프로젝트에서 직접 관리하는 대응표로 Unicode 이모지 별칭을 변환하고 저장 시 Unicode로 정규화한다. 초기 요구 예시는 `:smile:`, `:+1:`이며 전체 지원 목록은 아직 미확정이다. 알 수 없는 별칭은 유지하고, 이미지가 필요한 별칭은 지원하지 않는다. 코드·주석·Front Matter에서는 변환하지 않는다.

## 붙여넣기

브라우저의 기본 HTML 삽입을 차단하고 허용 노드로 변환한 후 Rust가 검증한다. 원본 HTML을 편집 DOM에 직접 삽입하지 않는다.

| 입력 | 결과 |
| --- | --- |
| 글자 크기·글꼴·색상, 셀 여백·음영·테두리 스타일 | 제거 |
| 굵게·기울임·취소선·첨자 | 의미만 지원 노드로 변환; 원본 스타일은 의미 판별에만 사용 |
| 제목·목록·인용문·표 | 지원 구조로 변환 |
| 병합 셀 | 영역을 일반 셀로 펼쳐 내용은 좌측 상단, 나머지는 빈 셀 |
| 셀 내부 여러 문단 | `<br>`로 연결 |
| 중첩 표 | 셀 내부 텍스트로 단순화 |
| 일반 탭 구분 텍스트 | 탭을 공백으로 변환; 탭만으로 표 생성 안 함 |
| 일반 텍스트 Markdown | 지원 문법을 해석하고 리치 요소로 변환 |
| 스크립트·이벤트 | 실행 가능한 형태로 삽입하지 않음 |
| 클립보드 이미지 | 임베딩 이미지 삽입 흐름 적용 |

파일 원문 불러오기와 외부 HTML 붙여넣기는 별개 정책이다. 파일의 미지원 원문·속성은 보존하지만, 붙여넣은 임의 스타일은 문서 속성으로 저장하지 않는다.

## 보존 불변식

1. 지원 문서는 불러오기 → 편집 → 저장 → 재열기 후 의미와 구조가 유지된다.
2. 정규화된 문서는 다시 정규화해도 결과가 바뀌지 않는다.
3. 미지원 구문·미허용 속성·Front Matter는 조용히 삭제되지 않는다.
4. 코드·주석·Front Matter 안에서 본문 변환이 실행되지 않는다.
5. 화면에 편집 가능한 형태로 남는 서식은 저장 가능한 형태여야 한다.

현재 구현과 전체 표준 적합성의 차이는 [호환성](compatibility.md)에 기록한다. 브라우저/ABI로 가져온 CRLF/CR은 내부 LF로 정규화한다.

## 확장 문법 추가 결정 (2026-10-23)

[Markdown Guide 확장 문법](https://www.markdownguide.org/extended-syntax/)의 항목을 지원 범위에 반영한다. 사용자 요청에 따라 **`~아래첨자~`, `^위첨자^` Markdown 문법은 제외**한다. 기존 원문 HTML의 sub/sup 허용 정책은 유지한다.

- 하이라이트는 한 줄 안의 `==내용==`이다. 빈 내용·양끝 공백·미완성 구분자·세 개 이상 연속 등호는 하이라이트로 해석하지 않는다. 내부 인라인 서식을 허용하며 이스케이프·코드·주석·Front Matter는 보호한다. 원문 HTML `mark`는 속성 없이 허용한다.
- 제목 마지막에 공백과 `{#custom-id}`를 붙이면 사용자 ID가 된다. ID는 비어 있지 않은 Unicode 문자/숫자 및 `_`, `-`, `.`, `:`만 허용한다. 잘못된 표현은 원문으로 남긴다. 중복 제목 ID는 문서 순서대로 `-1`, `-2` 등을 붙여 구분한다. ID 부분은 정규화로 수정하지 않는다.
- 정의 목록은 용어 다음 줄의 `: 정의` 형식이다. 여러 정의·여러 용어와 4칸 들여쓴 연속 줄을 지원한다. 중첩 블록 목록 전체 문법을 정의 안에 재귀 적용하는 기능은 포함하지 않는다. 원문을 보존하고 dl/dt/dd로 표시한다.
- 코드 언어 이름을 보존하며 지원 언어에는 고정 CSS 토큰 색상을 적용한다. 기본 문자열·숫자·리터럴, 주요 스크립트 언어의 키워드·주석을 분류하는 어휘 분석이며 완전한 언어 파서는 아니다. 미지원 언어는 일반 코드로 표시한다.
- 이모지는 Unicode 입력을 그대로 보존하며 `:tent:`, `:joy:`를 프로젝트 별칭 표에 추가한다. 미지원 별칭은 그대로 표시한다.

확장 문법 전체를 하나의 공통 표준으로 보장하지 않는다. 이 프로젝트의 수용 범위와 한계는 [호환성](compatibility.md)에 명시한다.
