# 편집 모드

모드 이름은 `rich`, `hybrid`, `markdown` 세 가지이며 기본값은 `rich`다. 드롭다운 순서도 리치 → 하이브리드 → 마크다운이다. 원본·HTML·읽기는 별도의 화면 전환이다.

| 모드 | 표시 및 편집 |
| --- | --- |
| `rich` / 리치 | 하이브리드와 같은 원문 기반 편집. 모든 문법을 리치로 유지하고 커서 진입 시에도 원문을 노출하지 않는다. |
| `hybrid` / 하이브리드 | 렌더링한 결과를 표시하고 커서가 진입한 문법의 원문을 노출한다. 문법별 생성자 옵션으로 리치 유지를 지정할 수 있다. |
| `markdown` / 마크다운 | 모든 원문을 항상 표시한다. 제목 크기, 강조, 코드 등의 스타일을 적용하며 Markdown 기호·빈 줄·HTML 원문·문자 참조를 숨기지 않는다. |

기존 하이브리드의 고정된 문법 노출 목록은 제거했다. 기존 Markdown 모드의 커서 진입 노출 동작은 새 하이브리드로 이동했다. `mode: 'markdown'`의 의미는 항상 보이는 스타일 적용 원문 편집으로 변경되었다. 기존 통합 코드는 이 동작 변경을 고려해야 한다.

## 생성자 설정

```html
<script src="./sohjae.js"></script>
<div id="editor"></div>
<script>
const editor = new Sohjae({
  selector: '#editor',
  mode: 'hybrid',
  elements: {
    table: { reveal_markdown: false },      // 표는 리치 유지
    image: { reveal_markdown: false },      // 이미지는 리치 유지
    code_block: { reveal_markdown: false }, // 코드 블록은 리치 유지
    bold: { reveal_markdown: true },        // 커서 진입 시 **원문** 표시
    heading: { reveal_markdown: true }
  }
});
</script>
```

생략한 문법의 하이브리드 기본값은 `reveal_markdown: true`다. `false`는 리치 유지, `true`는 커서가 해당 문법 범위 안에 있을 때 원문 노출이다. 중첩된 문법에서는 해당 위치의 가장 안쪽 노출 대상이 우선한다. 옵션은 `set_options({ elements: ... })`로도 변경할 수 있다.

주요 키: `heading`, `bold`, `italic`, `strikethrough`, `highlight`, `subscript`, `superscript`, `inline_code`, `link`, `image`, `list`, `quote`, `table`, `code_block`, `rule`, `footnote`, `definition_list`, `definition_term`, `definition`, `html`, `comment`.

이 옵션은 문법 지원을 켜고 끄는 설정이 아니다. 원문 텍스트로 처리되는 이모지·문자 참조 등은 별도 노출 대상이 아니다. 리치 모드와 마크다운 모드는 이 옵션에 따라 표시를 전환하지 않는다.

## 마크다운 모드

```js
new Sohjae({ selector: '#editor', mode: 'markdown' });
```

원문 각 행의 UTF-8 좌표를 유지하는 스타일 적용 편집 화면이다. `#`·`**`·링크 URL·코드 fence·표 구분자도 항상 표시된다. 구분자는 흐린 색으로 표시하고, 본문에는 제목·굵게·기울임·취소선·하이라이트·코드·링크 스타일을 적용한다. 코드 블록 안의 `#`는 제목 스타일을 적용하지 않는다. Enter는 원문에 개행 하나를 삽입한다. 임의 원문 HTML은 실행하지 않고 텍스트로 표시한다.

표·이미지를 실제 요소로 렌더링하지 않으므로 마크다운 모드에는 표 행 이동 핸들과 블록 전환 드롭다운을 표시하지 않는다. 선택·입력·실행 취소·IME·협업은 기존 원문 기반 모델을 사용한다. ‘원본’ 화면은 스타일 없는 textarea다.

## 블록 전환 단축키

블록 드롭다운은 다음 순서를 사용하며, 단축키도 같은 블록 전체 전환을 실행한다. Windows/Linux는 Ctrl+Alt, macOS는 Cmd+Option을 누른다.

| 순서 | 유형 | 단축키 |
| --- | --- | --- |
| 1–6 | h1–h6 | Ctrl/Cmd + Alt/Option + 1–6 |
| 7 | pre > code | Ctrl/Cmd + Alt/Option + 7 |
| 8 | blockquote > p | Ctrl/Cmd + Alt/Option + 8 |
| 9 | div > details | Ctrl/Cmd + Alt/Option + 9 |
| 10 | p | Ctrl/Cmd + Alt/Option + 0 |

단축키는 리치·하이브리드·마크다운 편집에서 현재 최상위 블록에 적용한다. 표·목록 내부에는 적용하지 않는다. 읽기 전용·원본·HTML·읽기 화면과 IME 조합 중에는 실행하지 않는다. macOS Option 조합으로 key 값이 특수문자가 되어도 숫자 키의 code로 판별한다.

표 작성 중 이스케이프하지 않은 `|` 바로 뒤에서 Enter를 누르면 원문에 `\n` 하나만 삽입한다. 리치·하이브리드의 세 가지 문단 Enter 규칙보다 우선한다. 코드 안이나 이스케이프된 `\|`는 이 규칙의 대상이 아니다. 마크다운 모드는 원래의 한 개행 Enter 동작을 사용한다.

리치 모드와 표를 리치로 유지하는 하이브리드 모드에서 마지막 셀의 Tab은 맨 아래에 빈 행을 추가하고 새 행 첫 번째 셀로 이동한다. 그 외 셀의 Tab과 Shift+Tab은 기존 셀 간 이동을 사용한다. 빈 셀의 편집용 자리표시자는 원문이나 내보낸 HTML에 추가되지 않는다. 읽기 전용에서는 행을 추가하지 않는다.

하이브리드에서 목록 원문 노출이 켜져 있으면 커서가 진입한 항목 하나가 아니라 해당 `ul`·`ol` 컨테이너 전체를 원문으로 표시한다. 중첩 목록과 항목의 인라인 문법도 포함한다. 커서가 목록을 벗어나면 리치 표시로 복원한다. `elements.list.reveal_markdown: false`는 목록 전체를 리치로 유지한다.

하이브리드에서 노출하는 원문과 마크다운 모드는 동일한 원문 토큰 렌더러를 사용한다. 같은 원문 범위의 UTF-8 좌표, 강조·코드·구분자 스타일을 공유한다. 하이브리드는 커서가 진입한 문법 범위만 노출하고 마크다운 모드는 문서 전체에 항상 적용한다.

표 원문 노출은 마크다운 모드와 같은 `markdown_line` 행 요소를 유지한다. 하이브리드에서는 `<table>` 대신 원문용 컨테이너에 이 행들을 넣어 표의 구분선과 본문 행이 각각 별도 줄을 차지하도록 한다.

하이브리드 표 원문 끝에서 Enter를 누르면 추가한 빈 줄을 표 원문 편집 범위에 유지하고 커서를 그 줄로 옮긴다. 새 행이 아직 완성되지 않아 파서가 표 밖으로 분류하더라도 원문 입력을 계속할 수 있다. 커서가 편집 범위를 벗어나면 일반 표시 규칙으로 돌아간다.

`&nbsp;`만 있는 줄은 편집기의 명시적 빈 문단이므로, 표에 바로 이어져도 표 행으로 흡수하지 않는다. `| &nbsp; | |`처럼 셀 구분자가 있는 행은 기존대로 표 행이다.

하이브리드 표 원문 끝에서 Enter로 새 줄을 만든 뒤 `| `를 입력하면 기존 표의 열 수에 맞춰 빈 행의 구분자를 완성한다. 완성된 행은 하이브리드 원문에도 즉시 표시하고 커서는 새 행 첫 번째 셀에 둔다.

리치 모드는 별도의 HTML 직접 편집 엔진을 사용하지 않는다. 하이브리드와 같은 렌더링·UTF-8 좌표 매핑·입력·IME·협업 경로를 사용한다. `elements.*.reveal_markdown` 옵션은 리치 모드에서 적용하지 않고 항상 false로 취급한다. HTML 화면에는 기존대로 추적 요소를 제거한 렌더링 결과를 표시한다.

하이브리드에서 인라인 요소의 렌더링된 오른쪽 끝에 커서가 닿아 원문이 처음 노출될 때는 닫는 문법 기호 뒤에 커서를 둔다. 예를 들어 `**원본 화면**을`에서 `을`을 지나 왼쪽으로 진입하면 `**원본 화면**|을` 위치다. 이미 노출된 원문 안에서는 기호를 포함한 문자 단위 이동을 유지한다.

## 하이브리드 편집 정책 위임

하이브리드에는 별도의 입력·삭제·Enter 알고리즘이 없다. 현재 원문 노출 범위 안의 선택은 마크다운 편집 정책, 리치로 유지된 범위는 리치 편집 정책을 사용한다. 원문 노출 여부는 생성자의 `elements.*.reveal_markdown`과 현재 커서 범위로 결정한다. 일반 문단처럼 별도의 노출 문법이 없는 범위는 리치 편집 정책을 따른다.

이 규칙은 이전의 하이브리드 전용 목록 기호 삭제·문단 전환 규칙을 대체한다. 원문으로 노출된 목록에서는 마크다운 모드처럼 입력한 문자만 삭제하고 Enter는 개행 하나를 삽입한다. 리치 유지 목록은 리치 모드와 같은 구조 편집을 사용한다. 표의 새 줄 `| ` 자동 완성은 공통 마크다운 입력 처리이며 마크다운 모드와 원문 노출 하이브리드에서 모두 동일하게 적용한다.

협업 원문에서 표 경계를 바꾸는 파이프·개행 편집은 표와 인접 본문을 함께 조정한다. 새 행 자동 완성 후 최초 입력한 `|`를 별도 본문으로 남기지 않는다.

원문 편집에서 입력 후 커서는 삽입한 원문의 UTF-8 바이트 바로 뒤에 둔다. 협업 투영 앵커가 문서 끝의 새 개행 앞을 가리키더라도 원문 편집의 커서를 이전 줄로 되돌리지 않는다.

목록과 표는 공통 원문 편집 범위를 사용한다. 하이브리드에서 원문이 노출된 목록의 마지막 항목 뒤에 Enter를 입력하면 새 빈 줄도 노출 범위에 유지한다. Enter·문자 입력 자체는 마크다운 편집 정책에 그대로 위임하며, 커서가 범위를 벗어나면 목록을 리치 표시로 복원한다.

표·목록 원문 편집 중 마지막 항목 뒤에서 Enter를 한 번 누르면 새 줄에서 원문 편집을 유지하고, 그 빈 줄에서 다시 Enter를 누르면 블록 원문 편집을 종료한다. 블록은 리치 표시로 복원하고 아래에 `&nbsp;` 일반 문단을 만들어 커서를 둔다. 이 동작은 공통 원문 블록 종료 규칙으로 처리한다.

## Live Preview 기본 동작 (현재 기준)

이 절은 앞서 기록된 하이브리드 원문 편집의 빈 문단·Enter 규칙을 대체한다. Obsidian Live Preview의 기본 원칙에 맞춰 활성 텍스트 블록은 원문으로 편집하고, 비활성 블록은 렌더링한다. 문법별 리치 유지 옵션은 계속 지원한다. 표를 포함한 모든 Obsidian 동작·확장과의 완전한 호환성을 뜻하지는 않는다.

- 일반 Enter는 원문 개행 하나, 문단 구분은 빈 줄이다. 원문 편집에 `&nbsp;`를 자동 삽입하지 않는다.
- 목록에서 Enter는 같은 불릿, 다음 번호, 미체크 작업 항목을 이어 쓴다. 빈 항목에서 Enter는 목록을 종료하고 일반 문단으로 이동한다.
- Shift+Enter는 두 공백과 개행으로 Markdown 줄 바꿈을 삽입한다. `<br>` 문자열을 끼워 넣지 않는다.
- Tab·Shift+Tab은 원문 행을 들여쓰기·내어쓰기한다. 인용문 Enter도 접두사를 이어 쓰고 빈 인용문에서는 종료한다.
- Backspace·Delete·선택 삭제는 원문 좌표를 따른다. 단어 삭제도 문자 하나 삭제로 바꾸지 않는다.
- 문법 기호를 삭제해 파싱 결과가 바뀌어도 편집 중인 블록의 원문 표시와 커서 범위를 유지한다.
- 원문 붙여넣기는 HTML 재변환이나 탭 공백 치환 없이 일반 텍스트를 사용한다. 한글 IME도 같은 원문 범위에서 처리한다.

현재 검사 페이지는 `web/live-preview-tests.html`이다. 과거 HTML 직접 편집·단계별 정책 검사 소스는 이전 동작 기록용이다.
